# DZO Plan Autofill

Userscript для **Tampermonkey**, який автоматизує заповнення форми річного плану закупівель на [DZO](https://www.dzo.com.ua/).

Скрипт призначений для автоматичного перенесення даних із договору в PDF у форму **«Редагування запису в річному плані закупівель»**.

> **Статус:** 🟢 Працююча версія
> **Платформа:** DZO (`dzo.com.ua`)
> **Тип:** Tampermonkey Userscript
> **Файл:** `dzo-plan-autofill.user.js`

---

## Можливості

Після встановлення userscript на сторінці редагування плану з'являється плаваюча панель керування з основними полями:

* **Сума**
* **Назва предмету закупівлі**
* **Код ДК 021 (CPV)**
* **Код КЕКВ**
* кнопка **«Заповнити форму»**

Скрипт послідовно заповнює необхідні поля та працює з динамічними елементами сторінки DZO, включаючи `iframe`, AJAX-завантаження та `Chosen`.

---

## Автоматизовані поля

### 1. Тип процедури

Встановлюється:

```text
Закупівля без використання електронної системи
```

Технічне значення:

```text
select[name="plan_method"] = "limited_reporting"
```

---

### 2. Очікувана вартість

Заповнюється поле:

```text
input[name="data[budget][amount]"]
```

Значення береться із введеної суми.

---

### 3. Конкретна назва предмету закупівлі

Заповнюється:

```text
input[name="data[budget][description]"]
```

Важливо: це поле належить саме до плану закупівлі.

На сторінці DZO існують інші поля `description`, зокрема:

```text
data[items][0][description]
```

Вони не використовуються для заповнення назви предмету закупівлі.

Поле плану також пов'язане з перемиканням мовних вкладок:

```text
УКРАЇНСЬКА / IN ENGLISH
```

---

## 4. Класифікація ДК 021 (CPV)

Вибір класифікатора виконується через стандартний механізм DZO.

Скрипт:

1. натискає кнопку вибору класифікації;
2. відкриває вікно класифікатора;
3. знаходить `iframe`;
4. знаходить поле пошуку `input#search`;
5. вводить код;
6. очікує фільтрацію дерева `jsTree`;
7. знаходить необхідний вузол;
8. вибирає його;
9. натискає кнопку підтвердження `a#select`.

Наприклад:

```text
18330000-1
```

перетворюється для пошуку вузла:

```text
cl_DK021_18330000_1
```

Тобто дефіс у коді замінюється на підкреслення.

---

## 5. Код КЕКВ

КЕКВ працює за тим самим механізмом, що й ДК 021.

Для відкриття класифікатора використовується:

```text
a.choiceClass[data-class="КЕКВ"]
```

Усередині `iframe` виконується пошук через:

```text
input#search
```

Необхідний елемент має формат:

```text
cl_KEKV_<код>
```

Наприклад:

```text
2210
```

→

```text
cl_KEKV_2210
```

Після вибору вузла виконується підтвердження:

```text
a#select
```

# 6. Джерело фінансування

Скрипт автоматично додає блок джерела фінансування через:

```text
#multiBreakdowns a.addMultiItem
```

Після додавання блока автоматично заповнюються необхідні поля.

### Тип джерела

```text
Місцевий бюджет
```

Технічне значення:

```text
local
```

---

### Сума

Використовується та сама сума, що й для очікуваної вартості.

---

### Країна

```text
Україна
```

Значення встановлюється за замовчуванням сайтом.

---

### ТПКВКМБ

```text
5061
```

Поле є динамічним `select` із класом:

```text
js-choosenInit
```

Опції завантажуються AJAX після вибору типу джерела.

Скрипт очікує завантаження необхідного значення протягом визначеного тайм-ауту.

---

### Категорія КАТОТТГ

```text
Місто
```

Також є динамічним AJAX-select.

---

### Область

```text
Черкаська область
```

Значення завантажується динамічно після вибору відповідних параметрів.

---

### Населений пункт

```text
м. Черкаси
```

---

### Вулиця

```text
вул. Пастерівська, 102
```

---

### Поштовий індекс

```text
18003
```

# Порядок виконання

Послідовність виконання операцій є важливою через залежності між елементами форми DZO.

Поточний порядок:

```text
Основні поля
      ↓
ДК 021
      ↓
КЕКВ
      ↓
Джерело фінансування
```

У коді весь процес запускається через:

```javascript
runAll()
```

# Що навмисно НЕ автоматизовано

Деякі поля залишені для ручного заповнення.

### Рік планування

Не змінюється скриптом.

---

### Валюта

Не змінюється.

Залишається стандартне значення:

```text
UAH
```

---

### Орієнтовний початок проведення процедури

Не автоматизується.

Причина — поле використовує `datepicker`, а доступні дати мають специфічні обмеження. Зокрема, вибір прив'язаний до першого числа місяця.

Дата встановлюється користувачем вручну.

---

### Публікація плану

Кнопка:

```text
Опублікувати
```

не натискається автоматично.

Фінальна перевірка та публікація виконуються користувачем вручну.

Це зроблено навмисно, щоб перед публікацією можна було перевірити всі заповнені дані.

---

# КАТОТТГ

Окремо потребує перевірки автоматичний вибір населеного пункту КАТОТТГ.

Передбачається пошук:

```text
Черкаси
```

та вибір відповідного варіанта:

```text
UA71080490010015879
```

Ця частина потребує додаткового тестування безпосередньо на живому попапі DZO.

На поточному етапі саме цей механізм вважається найбільш потенційно нестабільним компонентом userscript.

# Встановлення

## 1. Встановити Tampermonkey

Встановіть розширення **Tampermonkey** для браузера.

## 2. Створити userscript

Створіть новий userscript у Tampermonkey.

## 3. Додати код

Скопіюйте вміст:

```text
dzo-plan-autofill.user.js
```

до створеного userscript.

## 4. Відкрити план закупівлі

Перейдіть на сторінку:

```text
https://www.dzo.com.ua/plans/{id}/edit
```

де `{id}` — ідентифікатор необхідного плану.

Після завантаження сторінки повинна з'явитися плаваюча панель керування.

---

# Використання

1. Відкрити необхідний план закупівлі.
2. Перевірити дані договору.
3. Ввести у панель:

   * суму;
   * назву предмету закупівлі;
   * код ДК 021;
   * код КЕКВ.
4. Натиснути **«Заповнити форму»**.
5. Дочекатися завершення автоматичного заповнення.
6. Перевірити всі поля.
7. За необхідності вручну встановити:

   * рік планування;
   * дату початку процедури.
8. Самостійно перевірити правильність усіх даних.
9. Натиснути **«Опублікувати»** вручну.

# Особливості реалізації

Userscript враховує особливості внутрішньої логіки DZO:

* динамічне створення блоків форми;
* `iframe` для класифікаторів;
* `jsTree`;
* AJAX-завантаження опцій;
* `Chosen`;
* асинхронну появу елементів DOM;
* необхідність виконання операцій у певній послідовності.

Через це просте встановлення `.value` для деяких полів недостатнє — необхідно імітувати дії користувача та дочекатися завершення внутрішніх процесів сайту.

## Призначення

Проєкт створений для зменшення кількості ручної роботи під час перенесення даних із договорів до річного плану закупівель на DZO.

Скрипт **не приймає рішення щодо змісту закупівлі** та не виконує публікацію автоматично. Він лише автоматизує технічне заповнення форми на основі даних, введених користувачем.




=====================================================
Проект: автозаполнение плана закупівлі на dzo.com.ua (Tampermonkey)

Задача: автоматизировать заполнение формы "Редагування запису в річному плані закупівель" на https://www.dzo.com.ua/plans/{id}/edit данными из PDF-договора (КУ ЧОР "Черкаський обласний центр фізичного здоров'я населення "Спорт для всіх"").

Реализация: userscript под Tampermonkey, файл dzo-plan-autofill.user.js. Добавляет плавающую панель на странице с полями: Сума, Назва предмету закупівлі, Код ДК 021 (CPV), Код КЕКВ, кнопка "Заповнити форму".

Уже работает и подтверждено вживую:
Тип процедури → select[name="plan_method"] = limited_reporting ("Закупівля без використання електронної системи")
Очікувана вартість → input[name="data[budget][amount]"]
Конкретна назва предмету закупівлі → input[name="data[budget][description]"] (важно: НЕ data[items][0][description] — это была первая ошибка, поле называется одинаково, но это разные инпуты; description относится к полю плана, которое переключается вкладками УКРАЇНСЬКА/IN ENGLISH)
Класифікація за ДК 021 (CPV) и Код КЕКВ — оба через одинаковый механизм:
Клик по a.choiceClass[data-class="ДК021"] (или "КЕКВ") открывает div.info с iframe того же домена (src="/js/classifications/universal/index.htm?...shema=...")
Внутри iframe: input#search — вписываем код, дерево (jsTree) фильтруется
Нужный узел ищется по id cl_<PREFIX>_<код_с_подчеркиваниями> (для ДК021 PREFIX=DK021, код 18330000-1→18330000_1; для КЕКВ PREFIX=KEKV, код 2210)
Клик по узлу выделяет его, затем клик по кнопке a#select (id, не текст! — текст "Вибрати" рисуется через CSS) подтверждает выбор и закрывает попап
Джерело фінансування:
Клик по #multiBreakdowns a.addMultiItem добавляет блок (шаблон лежит в скрытом #tpls, index в имени полей подставляется рендерером сайта)
Тип джерела = local (Місцевий бюджет) — селект select[name*="[title]"]
После выбора типа сайт сам показывает скрытые строки (Країна/ТПКВКМБ/КАТОТТГ/область/…)
Сума = та же сумма, что и очікувана вартість
Країна = "Україна" (и так по умолчанию)
ТПКВКМБ = "5061" — select с классом js-choosenInit (Chosen), опции подгружаются AJAX'ом после выбора типа джерела, скрипт ждёт до 8 сек
Категорія КАТОТТГ = "Місто" (тоже AJAX-select)
Область = "Черкаська область" (тоже AJAX-select)
Населений пункт / Вулиця / Індекс — обычные текстовые инпуты, статичные значения (м. Черкаси / вул. Пастерівська, 102 / 18003)
Порядок выполнения (важно для сайта): основные поля → ДК021 → КЕКВ → джерело фінансування (в такой последовательности сейчас и вызывается в runAll())
Сознательно НЕ автоматизировано:
Рік планування (не трогаем)
Валюта (не трогаем, дефолт UAH)
Дата "Орієнтовний початок проведення процедури" — datepicker, выбор ограничен только 1-м числом месяца, решили не трогать, выбирается вручную
Кнопка "Опублікувати" — всегда вручную, после проверки
Требует проверки / потенциально хрупкое место:
Поиск КАТОТТГ (текстовое поле с автоподсказками, ищем "Черкаси", ожидаемый id варианта UA71080490010015879) — это единственная часть, которая была написана "вслепую" по статической разметке, без реальной проверки живого попапа с подсказками. Ещё не подтверждено, работает ли клик по подсказке корректно — это следующий пункт для проверки/починки.
